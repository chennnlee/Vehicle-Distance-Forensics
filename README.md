# 行車紀錄器車速與車距量測

從一般行車紀錄器的影片,量出自己的車速,以及周圍車輛的距離與時速。量不準的情況,系統會直接標示出來,不硬給數字。

政治大學資訊科學系大學部專題,指導教授:彭彥璁老師。題目:以 AI 深度估算模型為基礎的單鏡頭影像行車距離量測方法。

## 做法

1. **自己的車速**:車道虛線的長度和間隔是法規訂的(台灣是 4 公尺線段加 6 公尺間隔,依《道路交通標誌標線號誌設置規則》第 182 條)。程式在畫面上固定的位置看著虛線一段一段經過,算出經過的週期,再換算成車速。這一步不需要知道鏡頭的參數。
2. **周圍車輛的距離**:先用 [SHARP](https://github.com/apple/ml-sharp)(單張影像的 3D 重建模型)從一張畫面重建出路面,得到路面所在的平面。每一張畫面再用 YOLO 找出車輛,以及車輪碰到地面的位置,把這個點投到路面上,就得到距離。比例尺用車道寬(3.5 公尺)校正,前後方向再用「虛線經過畫面不同高度的時間差」校正一次。
3. **周圍車輛的時速**:自己的車速,加上兩車距離變化的速度。
4. **量不準就標示**:距離太遠、看不到虛線、正在換車道時,畫面和輸出檔都會註明,不給數字。

## 準確度

| 量什麼 | 怎麼驗證 | 結果 |
|---|---|---|
| 自己的車速 | comma2k19 兩台車、34 段各 1 分鐘的高速公路影片,和車上定位系統比對 | 平均誤差 2.9 km/h。其中一段是高速公路之間的連接道,虛線間隔和主線不同,這段單獨的誤差是 40 km/h;不算這段時是 2.2 km/h |
| 自己的車速(台灣) | 一支國道影片分成 12 段,和人工逐格計算的車速比對 | 平均誤差 0.7 km/h |
| 自己的車速(台灣) | 另一批 8 支影片、28 段,和人工逐格計算的車速比對 | 平均誤差 1.9 km/h |
| 周圍車輛的距離 | comma2k19 三段影片,和車上雷達比對,約 32 公尺內 | 誤差的中位數 5–7% |
| 周圍車輛的時速 | 同上 | 平均誤差 3.5 km/h |
| 32 公尺外的距離 | 同上 | 誤差約 20%,所以畫面不顯示數字 |

怎麼解讀:

- 距離誤差 7%,代表雷達量到 20 公尺時,我們的結果大約落在 18.6–21.4 公尺。
- 距離誤差寫成 5–7%,是因為雷達從車頭量起、我們從擋風玻璃後的鏡頭量起,兩者的起點差約 1.5–2.3 公尺。直接比是 7.0%,扣掉起點差是 5.1–5.8%。
- comma2k19 的第一台車在開發時就用過。完全沒用來調整程式的第二台車,15 段的平均誤差是 4.2 km/h,其中包含上面那段連接道。

每個數字用了哪些資料、怎麼算,見 [docs/VALIDATION_STATUS.md](docs/VALIDATION_STATUS.md)。

## 已知限制

- 32 公尺外的距離偏差約 20%,只標示,不給數字。
- 一支影片如果跨過不同種類的道路(例如從市區道路開上高速公路),虛線間隔會變,車速會在交界處算錯。
- 夜間車燈照到的反光路釘比漆線還亮,會干擾虛線訊號,夜間誤差比白天大。
- 影片每秒的張數要夠多:每經過一段虛線,至少要拍到約 8 張。以 10 公尺的虛線、時速 100 公里來說,每秒至少要 22 張。
- 從旁邊擦身而過的車,車輪碰地的位置會沿著車身移動,只能給距離,不能給時速。

完整清單見 [docs/FAILURE_BOUNDARIES.md](docs/FAILURE_BOUNDARIES.md)。

## 怎麼重跑

- 只用公開資料集、不需要 3D 重建的完整路徑,以及每項結果的預期數字:[REPRODUCE.md](REPRODUCE.md)
- 套件:`pip install -r requirements.txt`,另外需要 `ffmpeg`
- 首頁示範影片的產生方式:先用 `tools/dashcam_range_speed.py` 量測一段 comma2k19 影片,再用 `tools/report/render_demo_video.py` 畫成中文畫面。後者只畫圖、不重新量測,參數寫在檔案開頭的說明裡。

各工具的用途、輸出資料夾與其他文件的說明,見 [docs/REPO_GUIDE.md](docs/REPO_GUIDE.md)。
