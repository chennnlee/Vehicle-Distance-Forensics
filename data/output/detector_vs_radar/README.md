# 換偵測器會不會讓量測變準?—— 對原廠雷達的受控比較(2026-09-16)

## 一、這一輪在回答什麼

本系統量他車距離的方式是:**偵測器**(目前 `yolov8m-seg`)吐出車輛遮罩 → 取遮罩底緣當
**接地點**(車輪與路面接觸的那一列像素)→ 該像素射線與**地面平面**求交,得到前向距離 →
距離對時間微分再加上**自車速**(虛線碼表法),得到目標的絕對速度。

報告表 8 與結論章原本寫著「偵測器與接地點鏈之雜訊約 **0.4 km/h**」,並據此主張
投資應放在尺度錨而非更換模型。**那個 0.4 來自 dc006 的「跟車自洽」檢查,而該檢查是循環的**
(`abs = ego + rel`,篩穩定跟車就是篩 `|rel|` 小),所以它既不能證明偵測器好、也不能證明偵測器壞。

2026-09-01 的雷達驗證提供了第一個非循環的替代品,於是這題第一次可以被真正回答:

> 把偵測器換成偵測級分數更高的 `yolo11x-seg`,對照原廠雷達,量測誤差會不會下降?

## 二、比較必須受控,否則比到的是別的東西

⚠ **不能只是「跑兩次評估器再比 MAE」。** `comma2k19_radar_eval.py` 對每個雷達物體只保留
**一條**我方軌跡(一對一眾數配對)。換一個偵測器,可能由**另一個時段**的軌跡贏得那個眾數,
於是兩次評估打分的是**不同的車、不同的時間**。

seg21 就是這樣:

| 執行 | radar_obj 2 配到的幀 | 該段雷達距離 | 自車速項 MAE |
|---|---|---|---|
| v8m | f592–718 | 7.4–23.5 m | 3.64 |
| 11x | f734–1053 | 24.6–44.2 m | **11.49** |

自車速項會跳成 11.49,而**自車速根本不經過偵測器**——兩次執行的 `ego_speed.csv`
**逐位元相同**(已驗證)。端到端 MAE 2.88 → 11.05 幾乎全部來自「打分的幀不同」,
不是量測變差。

**受控做法**:取兩次執行在 `(影格編號, 雷達物體編號)` 上的**交集**。同一瞬間、同一台實體車、
同一個平面、同一個尺度、同一組碼表讀數;唯一不同的是偵測器圈出哪些像素。
工具:`tools/detector_radar_compare.py`。共同配對 **547 幀**(seg21 82 / seg6 262 / seg10 203)。

## 三、結果

### 接地點本身幾乎沒有動

| 量 | 值 |
|---|---|
| 接地點像素列 \|Δpy\| 中位 | **0.00 px**(**85%** 的幀落在完全相同的一列) |
| 同上 p90 / max | 1.8 px / 9.1 px |
| 兩模型算出的距離差 \|Δrange\| 中位 | 0.040 m(p90 1.02、max 4.73) |

### 誤差是兩個模型共有的,不是偵測器產生的

| 相關係數 | 值 |
|---|---|
| 兩次執行「距離誤差 vs 雷達」的相關 | **r = 0.9986** |
| 兩次執行「幾何項誤差」的相關 | r = 0.6193 |

若誤差主要由偵測器造成,換一個結構不同的偵測器後,誤差序列應大致互相獨立。
實測是距離誤差幾乎完全重合 → **那個誤差來自兩者共用的環節**(尺度、平面、或雷達自身),
不是來自偵測器。

### 配對差:速度沒有改善,距離有一點

負值代表 11x 較好。⚠ **以 block CI 為準**:連續幀不是獨立樣本(同一台車的相鄰幀一起動),
naive CI 假設獨立會把區間縮得太窄;block CI 以 20 幀(1 秒)為單位重抽。

| 分層 | n | 距離 \|誤差\| 配對差 | block 95% CI | 幾何項(速度)配對差 | block 95% CI |
|---|---|---|---|---|---|
| 全部 | 547 | −0.152 m | −0.244 … −0.039 | +0.028 km/h | −0.675 … +0.781 |
| **近場 ≤32 m** | 178 | **−0.447 m** | −0.678 … −0.196 | −0.033 km/h | −0.544 … +0.675 |
| 遠場 >32 m | 369 | −0.010 m | −0.037 … +0.013 | +0.057 km/h | −1.002 … +1.160 |

近場距離相對誤差:**7.49% → 5.77%**(−1.72 個百分點)。

### 檢出量與成本

| | 觀測筆數(三段合計) | 目標數 | 每 1200 幀耗時 |
|---|---|---|---|
| v8m | 14,972 | 272 | 約 60 s |
| 11x | 16,034(+7.1%) | 285 | 約 90 s(**×1.5**) |

多出來的觀測大多落在遠場(far_field 旗標:8,988 → 9,901)。

## 四、結論

1. **目標絕對速度:偵測器不是瓶頸。** 547 個共同配對幀上,配對差 +0.03 km/h,
   block CI −0.68…+0.78 明確包含 0。**這是第一次用非循環的證據回答這題**
   (先前引用的 0.4 km/h 來自循環的跟車自洽檢查)。
2. **跟車距離:偵測器有可量測但小的貢獻。** 近場距離誤差由 7.49% 降到 5.77%,
   block CI 不含 0。但剩下的 5.8% 仍在,**換模型只買回全部距離誤差的約四分之一**。
3. 速度沒改善而距離有改善並不矛盾:改善的是**系統性偏移**(整體距離略偏),
   而速度取的是距離的**時間微分**,固定偏移在微分中消失。
4. 成本:推論時間 ×1.5。

**因此報告表 8 第一列的 0.4 km/h 應換成這裡的數字,並改寫其論證**:偵測器對速度無影響
(而非「雜訊小」),對距離有約 1.7 個百分點的影響,兩者都遠小於尺度校正的不確定度
(2~11%)與縱向距離尺度(11~32%)。投資順序的結論不變,但理由從一個循環的量
換成一個外部儀器量到的量。

## 五、限制(必讀,不要外推)

- **近場那一組實質上只有一台車**:178 幀中 171 幀是 seg6 的 radar_obj 1(一段連續跟車),
  獨立區塊只有 8 個。所以「近場距離改善 1.7 個百分點」的把握度遠低於 n=178 的表面樣本數,
  block CI 已反映這點,但仍應視為**單一情境的觀察**。
- **這測的是「換更大的現成同家族模型」,不是「微調」**。v8m 與 11x 都是 COCO 預訓練的
  YOLO 分割模型,共享同一套標註慣例——85% 的幀接地點落在完全相同的像素列,正是這件事的直接證據。
  → 本結果**排除**了「換現成模型」這條便宜路徑,但**不能**排除「針對接地點定義微調」
  (教授第 ④ 點)仍有收益。要回答那一題,需要的是重新定義遮罩底緣的標註,不是更大的模型。
- 三段皆為加州高速公路日間、單一車輛(comma2k19 `b0c9d2329ad1606b`)。
- 遠場的 20% 距離偏差兩個模型完全相同(配對差 −0.010 m)→ **遠場問題與偵測器無關**,
  是幾何靈敏度問題(已由 `far_field` 旗標標示)。

## 六、可重現性

**基準線先自我驗證過**:用重建的影格重跑 v8m,三段的 `ranges.csv` 與 `ego_speed.csv`
與 2026-09-01 封存輸出**逐位元相同**(僅行尾 CR 差異),評估器輸出亦完全重現
(seg21 geom MAE 2.6630、seg6 4.4608、seg10 5.1429)。所以本節的差異全部歸因於偵測器。

```bash
# 1) 影格(/tmp 會消失,要重建)
python3 tools/comma2k19_prepare.py --zip data/input/comma2k19/Chunk_1.zip \
  --out-root <frames_root> --same-route --truth can \
  --segments "b0c9d2329ad1606b|2018-08-15--09-01-03|21,b0c9d2329ad1606b|2018-07-29--11-17-20|6,b0c9d2329ad1606b|2018-08-17--14-17-47|10"

# 2) 兩個模型各跑三段。參數與 comma2k19_radar_eval/README.md 第三節完全相同,只換 --yolo-model
python3 tools/dashcam_range_speed.py --frames-dir <frames_root>/<segdir>/frames \
  --fps 20.0 --reference-pointcloud data/output/sharp_gaussians/c2k19_seg21_ref.ply \
  --pointcloud-scale 1.032805 --scale-cv 0.0188 --hood-y 630 \
  --odometer-points "426,500;370,540;313,580;266,615" --dash-cycle-m 14.63 \
  --yolo-model checkpoints/yolo11x-seg.pt --out-dir <out>/11x/seg21
# (seg6: scale 0.925076 cv 0.0229 點 "434,500;400,540;353,580;271,615";
#  seg10: scale 0.912122 cv 0.0282 點 "762,500;822,540;327,580;358,615")

# 3) 各自對雷達評估(radar.csv 沿用封存,雷達不受模型影響)
python3 tools/comma2k19_radar_eval.py --ranges <out>/11x/seg21/ranges.csv \
  --ego-speed <out>/11x/seg21/ego_speed.csv --tracks <out>/11x/seg21/tracks.json \
  --radar data/output/comma2k19_radar_eval/seg21/radar.csv \
  --gt <frames_root>/<segdir>/gt_both.csv --a-ours 1436.707330 --y-h-ours 365.181 \
  --out-json <eval>/11x_seg21.json --dump-csv <eval>/11x_seg21_pairs.csv
# (seg6: --a-ours 1290.617259 --y-h-ours 382.743;seg10: --a-ours 1197.038604 --y-h-ours 382.819)

# 4) 受控比較
python3 tools/detector_radar_compare.py --eval-dir <eval>
```
