# report_final — 四台路口 CCTV 測速成果(v3 追蹤品質管線)

每台攝影機一個資料夾(kh013 / hsinchu006 / kh012 / kh019),內容:

> **v3(2026-07-10)追蹤器修正**——針對「框跳動」與「同車重複計數」:
> 1. **同幀重複框抑制**:YOLO 常對同一台車同時發 car+truck 兩框(各自生軌=數兩次);
>    同尺寸群組、重疊率(交集/小框)>0.65 只留高信心框。
> 2. **類別群組關聯**:car/truck/bus 視為同群組再關聯(YOLO 類別閃爍不再剪斷軌跡),
>    回報類別=全軌觀測多數決。機車獨立群組,不與汽車互併。
> 3. **斷軌事後縫合**:偵測中斷>3s 令車輛以新 id 重生、速度被回報兩次;
>    現以等速外插落點+尺寸+方向閘門縫回,`tracks.json` 的 `merged_from` 記錄每次合併供稽核。
> 4. **遠場防護鏈**:遠場(靈敏度>0.3 m/px)觀測不參與速度擬合、不當縫合端點、
>    遠場軌跡關聯閘門鎖 4m——修掉「地平線漫遊」(退行車在地平線把對向車接進來污染擬合)。
> 5. **關聯閘門物理化**:舊 gate=speed×dt×1.6 在斷檔數秒後膨脹到數十公尺,會把遠方另一台車
>    縫進來捏造 ~100 km/h;改為速度誤差項+加速度上限(4 m/s²)項。
> 6. **影片顯示框平滑**:渲染時對框做置中 (¼,½,¼) 加權平均(保線性運動不滯後),
>    量測資料(tracks.json)保持原始值;時間斷點(縫合縫、掉幀)不平滑。
>
> 舊版(v2)的 speeds.csv/tracks.json 備份於各資料夾 `v2_backup/`。
> 同幀 A/B 驗證:配對軌速度差 median ≈ 0(kh012 n=113、kh013 n=15),
> 「A 軌消失後 B 軌在其外插位置出生」可疑對 kh012 由 8 降至 4。
> 注意:v3 影片由 original_h264.mp4 重建幀重跑(原幀目錄在 /tmp 已失),OSD 秒跳在
> 重編碼幀上偵測結果略有差異,時間軸與 v2 有 1~3 秒的局部平移;速度結論不受影響。

## 品質旗標(speeds.csv `quality` 欄 / 影片標籤樣式)
- `ok`:等速擬合 RMSE < 1.5 m → 彩色標籤 `idN car 34km/h`
- `nonuniform_motion`:RMSE ≥ 1.5 m(加減速/走走停停)→ 標籤加 `~`,數字為區間平均
- `far_field`:觀測點中位靈敏度 > 0.30 m/px(接近地平線,1 像素誤差=公尺級位移)→ 灰色 `far-range: no speed`,**拒絕輸出速度**(1110822 失效案的自動化)
- 顯示降級:±CI 超過速度一半(錯誤關聯/極不規則)→ 灰色 `27+-25km/h?`,BEV 不畫

## 速度不確定度
`speed_ci_kmh` = 1.96×(等速擬合斜率標準誤) ⊕ 1.96×(速度×校正尺度CV),二者平方和開根。
尺度CV 來自該相機車道虛線長度變異(kh013 7.4% / kh012 10.7% / kh019 6.0% / hsinchu006 5.9%)。

## 校正
scale 由台灣法定標線長度反推(lane_dash_calibration.py,多鏈剝離版):
- kh013:4m 車道線,scale 2.680;對向車道獨立次鏈 2.824(**跨車道相差 5.3%**)
- kh012:50cm 導引線,scale 2.227;4 條穩定次鏈 1.84–2.09(跨鏈 6–17%)
- kh019:50cm 導引線,scale 1.065
- hsinchu006:50cm 導引線,scale 1.169;4 條穩定次鏈 1.28–1.43(跨鏈 9–22%)

觀察:**4m 車道線的跨鏈一致性(~5%)明顯優於 50cm 導引線(10–20%)**——短標線的端點取樣誤差佔比大,可用時應優先選 4m 車道線當錨。
