# 事前登錄:前車相對速度與絕對速度(深度模型 × 虛線尺,對 comma2k19 原廠雷達)(2026-09-29)

**這份文件與程式 `tools/depth_dash_relspeed.py` 在任何預測產生之前 commit。**
commit 之後,下列規則與程式參數不再更動;若必須更動,另開一節寫明「看過什麼之後改的」。
延續 `docs/DEPTH_DASH_SCALE_PREREG.md`(commit `25dacd2`)的尺度 k 與自車速,**不重新量 k**。

## 1. 要驗證什麼

1. **前車相對速度** = 前車距離(k × 深度模型讀值)對時間的斜率。
2. **前車絕對速度** = 自車速(本方法由虛線剖面平移量推得,已封存)+ 相對速度。

真值:comma2k19 該車原廠 DSU 雷達的相對速度 `radar_rel_ms`,與 CAN 輪速 `can_ego_kmh`。
與我方完全不共用感測器。

## 2. 沒有用到組員程式,也不用雷達挑目標

- 方法程式只 import `cv2`、`numpy`、`ultralytics`(YOLO)、`depth_dash_scale`(Terry)。
  不 import `dashcam_range_speed`、`odometer_distance_calib`、`lane_line_fit`、`comma2k19_radar_eval`。
- **前車由影像自己決定**(與 demo `tools/report/demo_haisheng_dash_scale.py` 的定義相同):
  YOLO `yolov8m-seg`,conf ≥ 0.4,類別 car/bus/truck;框底中心落在**封存結果的本車道左右線之間**
  (該時窗沒有線時用畫面 0.3–0.7 寬),取框底最低(最近)者。
  接地讀值點 = (框中心 x, 框底 − 0.06 × 框高),深度取該點 5×5 中位數。
- **同一台車的連續判斷只用影像**:相鄰取樣(0.2 s)的前車框 IoU ≥ 0.3,且距離變化 ≤ 15%。
  不成立就斷段。**雷達在預測階段完全不讀**(`depth_benchmark` 的 `paired_*.csv` 是用雷達挑列的,這裡不用)。

## 3. 計算規則(事前定死)

| 項目 | 規則 |
|---|---|
| 取樣 | 沿用封存的深度圖:comma2k19 每 4 幀(20 fps → 每 0.2 s) |
| 時窗 | 以每個取樣點為中心、前後各 2 個取樣(共 5 點、0.8 s 跨度),**5 點都必須在同一段連續前車內** |
| 相對速度 | 5 點「距離 vs 時間」最小平方斜率(m/s;正 = 前車拉開) |
| 自車速 | 封存 `speeds` 中兩端影格都落在時窗內的讀值,**至少 3 筆**,取中位數 |
| 絕對速度 | 自車速 + 3.6 × 相對速度(km/h) |
| 尺度 k | 封存結果的 k(da3_metric:seg10 0.972、seg21 0.959);品質閘拒發的片不產生讀值 |

## 4. 評分規則(事前定死;只在封存之後執行)

- **雷達目標**:每個取樣影格取 |橫向| ≤ 1.8 m 的**最近**回波(與 `depth_benchmark_targets.py` 相同的本車道判定)。
  時窗 5 點必須是**同一個雷達 slot**,否則該時窗無真值。
- 真值相對速度 = 5 點 `radar_rel_ms` 平均;真值絕對速度 = 5 點 CAN 平均 + 3.6 × 真值相對速度。
- **主結果不做距離一致性配對**(我方前車與雷達最近回波是否同一台,照實算進誤差)。
  副結果另報「我方距離與雷達距離差 ≤ 25%」的子集,並報被排除的比例。
- 報:相對速度誤差 3.6 × (我方 − 雷達) 的 MAE、bias、中位 |誤差|、p90、±3 km/h 內比例;
  絕對速度同上;自車速項(我方 − CAN)同上;**覆蓋率** = 有雷達真值的時窗中我方有讀值的比例。
  按雷達距離分近場(< 32 m)與遠場。
- **對照組:「相對速度 = 0」**。這批高速公路目標多半與自車同速,不報這個對照,
  小的相對速度誤差看不出方法有沒有貢獻資訊。另報我方與雷達相對速度的相關係數。
- 主模型 `da3_metric`。其他模型(metric3d_v2 / unidepth_v2 / depth_pro)**用同一支程式、同一組參數**
  在其封存結果存在時補跑,列為附表。
