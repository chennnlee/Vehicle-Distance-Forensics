## 2. 環境:為什麼要另開一個 venv

六個 repo 的依賴**互相衝突**,無法裝在同一個乾淨環境裡:

| 衝突 | 實際狀況 | 處理方式 |
|---|---|---|
| `numpy` 版本 | depth-pro 釘 `numpy<2`、DA3 也釘 `numpy<2`,但 opencv-python 4.13 要 `numpy>=2` | 裝 numpy 2.5.3。實測兩個模型都正常運作,那兩個 pin 是保守值 |
| Python 版本 | DA3 的 `requires-python` 是 `>=3.9,<=3.13`,而 `<=3.13` 在 PEP440 下**不含 3.13.11** | `pip install --ignore-requires-python` |
| `open3d` | Python 3.13 沒有 wheel。但它只給視覺化用,推論不需要 | `--no-deps` 安裝後手動補推論真正需要的套件 |
| `moviepy.editor` | moviepy 2.x 移除了這個子模組,DA3 在 `utils/export/gs.py` import 它 | 在 `depth_backends.py` 裡塞 shim,**不修改 vendored 原始碼** |

所以環境建在 `~/venvs/depthbench`,用 `--system-site-packages` 繼承 base 的 torch
(省 3 GB 重新下載,也保證 CUDA 版本一致)。

### 2.1 重建環境的完整指令


```bash
$P tools/depth_model_benchmark.py run \
   --model depth_pro \
   --frames /tmp/seg21_frames --frame-glob "f{frame}.jpg" \
   --targets seg21_targets.csv \
   --out data/output/depth_benchmark/seg21_depth_pro.csv
```

## 5. 評估協定:為什麼一定要報 raw 與 scaled 兩欄

這是整個實驗設計裡最重要的一點。

- **`raw`** = 模型輸出的公尺直接拿來比。回答:**絕對尺度對不對**。
- **`scaled`** = 先乘上一個全域常數(取 `median(真值/預測)`)再比。這是深度文獻的標準
  median-scaling 協定。回答:**相對幾何對不對**。

兩欄一起看才能把兩種完全不同的失效分開:

| raw | scaled | 意義 |
|---|---|---|
| 差 | **好** | 幾何是對的,只有絕對尺度錯 → **法定標線尺度錨正好能修好**,這是支持本計畫方法的證據 |
| 差 | 差 | 相對幾何也錯 → 再怎麼錨定都救不回來 |

Depth Anything V2 是 affine-invariant **視差**,根本沒有公尺,所以只有 `scaled` 欄
(用最小平方擬 `depth = 1/(a·disp + b)`)。這正好示範計畫書講的「尺度歧義 Scale Ambiguity」。

### 指標

`AbsRel` / `RMSE` / `δ1` 是深度文獻標準指標(審稿人要看的);
`中位誤差%` 是本專案的報法,**可以直接跟雷達近場的 7.0% 對比**。

## 7. 已經看到的第一個結果(smoke 階段,5/5 backend 全部跑通)

同一張 `data/input/sample.jpg`(2048×1362),**同一台相機、同一個場景**,五個模型的輸出:

| backend | 類型 | 預測 fx | fx/寬 | 深度範圍 | **中位深度** |
|---|---|---|---|---|---|
| `depth_pro` | 度量 | 6575.5 px | **3.21** | 10.2 – 10000 m | **103.11 m** |
| `unidepth_v2` | 度量 | 3634.7 px | **1.77** | 13.9 – 579.8 m | **74.51 m** |
| `metric3d_v2` | 度量(給定內參) | 1629.2 px | 0.7955(我們餵的) | 3.7 – 147.4 m | **29.97 m** |
| `da3_metric` | 度量 | 不輸出 | — | 2.2 – 80.1 m | **22.75 m** |
| `depth_anything_v2` | **相對** | 不輸出 | — | 0 – 816.8(無單位) | — |
| (SHARP 的固定假設) | — | — | 0.7955 | — | — |

**兩個最直接的觀察:**

1. **四個度量模型對同一張圖的中位深度是 22.75 / 29.97 / 74.51 / 103.11 公尺——差 4.5 倍。**
2. **兩個會自估內參的模型對同一台相機的焦距差 1.81 倍**(3634.7 vs 6575.5),
   而且都遠離 SHARP 的固定假設 0.7955×寬。

這與 CLAUDE.md 既有的記錄同向:

> UniDepth v2 對 hs005 預測 fx=843(等於距離修正係數 0.53),比實測的 0.76 還過頭;
> SHARP 假設 1527(係數 1.0)則偏另一邊。→ **兩個模型的內參都不可信,物理量測才可信**

⚠ **這張圖不是有真值的評估素材**,上表只證明「模型之間彼此嚴重不一致」,**不能證明誰對誰錯**。
要判定誰對誰錯必須用 §4.2/4.3 的流程對雷達真值跑。但「四個 SOTA 模型差 4.5 倍」這件事本身
已經足以說明:**在沒有物理錨點的情況下直接採信任何單一模型的公尺數,是沒有依據的**——
這正是計畫書階段一要定義的「失效邊界」。

## 9. 已知限制(先寫下來,免得之後當成新發現)

1. **深度圖給的是沿光軸的 Z,不是沿射線的 range**,而雷達給的是縱向距離。
   目前直接以 Z 對比縱向距離,在前視、俯仰小的行車紀錄器視角下差異很小,
   但若要做嚴謹版本應由內參轉換。
2. **取樣點的定義會影響結果。** 目前在 targets CSV 指定的像素上取 5×5 中位數。
   要跟管線嚴格可比,targets 應由**同一組 YOLOv8m-seg 遮罩的接地點**產生
   ——否則比到的是「取樣點差異」而不是「深度模型差異」
   (這正是 2026-09-16 偵測器受控比較踩過的坑)。
3. **`metric3d_v2` 需要內參**,無內參時本工具沿用 SHARP 的固定 FOV 假設
   (`fx = 0.7955 × 寬`)。這是刻意的:讓它與 SHARP 的假設一致,量出的就是那個假設的代價。
4. **`da3_metric` 權重是 CC BY-NC 4.0**,見 §3 的警語。
5. Video-Depth-Anything 已 clone 且 import 通過,但**尚未寫成 backend**
   ——它是影片模型,介面與逐幀模型不同(需要整段一起餵),要另外處理。

## 11. 修過的一個 adapter bug(2026-09-16,記著別重蹈)

**`da3_metric` 一開始把 `pred.depth` 直接當公尺讀,那是錯的。**

`DA3METRIC-LARGE` 輸出的是**canonical depth**,不是公尺。它的 model card 寫
"multiplying by focal length gives metric depth",repo 自己的
`utils/alignment.apply_metric_scaling()` 把公式寫死了:

```python
focal_length = (intrinsics[..., 0, 0] + intrinsics[..., 1, 1]) / 2
return depth * (focal_length / 300.0)
```

而 `DepthAnything3.inference()` **不會**替你套用 —— 它回傳 canonical 張量,而且
`pred.intrinsics` 是 `None`、`pred.scale_factor` 是 `None`、`pred.is_metric` 是 `{}`。
所以呼叫端必須自己乘。修正前後在同一台前車上差 **8.68 → 11.60 m(+34%)**。

**兩個延伸結論:**

1. **DA3METRIC 不是 camera-agnostic。** 它跟 `metric3d_v2` 一樣需要焦距,
   它的「公尺」會完整繼承那個焦距的誤差。真正自估內參的只有
   `depth_pro` 與 `unidepth_v2` 兩個。
2. **教訓:模型「輸出公尺」這件事不能憑 API 欄位名稱認定。** `pred.depth` 這個名字
   看起來就是深度,實際是 canonical 值。**必讀 model card 與原始碼的後處理**。
   這與 CLAUDE.md 的既有教訓同型:「任何從未記錄的執行參數,先去反解,不要目視猜」。

## 12. ✅ 階段一正式結果:四個深度模型 vs 原廠雷達(2026-09-16)

### 12.1 素材與配對

comma2k19 Chunk_1 兩段,共 **285 個配對幀**(近場 <32 m 共 231 個):

| 段 | 保留列 | 距離範圍 | 中位 | 近場<32m |
|---|---|---|---|---|
| `2018-07-30--13-44-30_10` | 202/285 | 10.2 – 43.4 m | 21.8 m | 188 |
| `2018-08-15--09-01-03_21` | 83/282 | 8.4 – 47.2 m | 27.9 m | 43 |

**配對經過幾何自我驗證**:同一台車必須滿足 `d = A/(py − y_h)`。
robust fit 後 `corr(py, 1/d)` = **0.979 / 0.994**,反解地平線 `y_h` = **386.2 / 389.6**
——與專案既有的三個獨立量測吻合(車道線消失點 377.8 / 碼表 374.3 / SHARP 365.2)。

### 12.3 三個可以寫進報告的結論

**① 沒有任何模型的 raw 輸出可以直接用。**
最好的 `metric3d_v2` 看似 2.3%,但那是因為**我們餵給它的焦距假設恰好對這台相機幾乎正確**
——證據是它需要的修正 `k = 1.013 / 1.045 ≈ 1.0`。換一台假設不成立的相機,
它的 raw 誤差會等比例放大(本專案在台灣行車紀錄器上量到該假設差 11–32%)。
真正自估內參的兩個(`unidepth_v2` 15–16%、`depth_pro` 33–40%)**直接用都不及格**。

**② 但 scaled 之後幾乎全部變好 —— 這正是計畫書的核心論點被證實。**
乘上一個全域常數後,四個模型有三個落在 **2.1 – 4.4%**。
即「**相對幾何是對的,錯的只有絕對尺度**」→ **法定標線尺度錨修的就是這一項**。
這是支持本計畫方法的正面證據,不是負面結果。

**③ 新判別量:尺度常數 `k` 的跨段穩定性,決定「能不能一台相機校一次就好」。**
`metric3d_v2` 3.2%、`unidepth_v2` 3.1%、`da3_metric` 5.8% → **可以單次錨定**;
`depth_pro` **29.6%** → 同一台相機不同片段就需要不同的 k,**單次錨定無效**。
這個指標不在標準深度 benchmark(AbsRel/δ1)裡,但對本計畫的部署方式是決定性的。

### 12.4 ⚠ 必須一起寫的限制(否則會過度宣稱)

1. **與 7.0% 不是同條件比較。** 那個數字來自不同段落、不同距離分布,而且走的是
   完整管線(平面+尺度錨+追蹤),這裡只是「在接地點讀一個深度值」。**不可直接排名。**
2. **共模偏移 Δ 未扣除。** 雷達在保險桿、相機在擋風玻璃,擬合出的最佳 Δ 為
   **+2.05 m(seg10)/ −0.20 m(seg21)**,兩段不一致所以無法直接扣掉。
   它對**模型之間的排名沒有影響**(共模),但會讓絕對 % 全體偏移。
3. **seg21 近場只有 43 列**,且兩段都是同一台車(comma2k19 Chunk_1 只有一台車)。
   跨車輛未驗證。
4. **只測「在接地點讀深度」這一種用法**,沒有測 BEV 反投影、沒有測多模型融合。
5. `metric3d_v2` 與 `da3_metric` 的 raw 欄**本來就依賴我們餵的焦距**,
   嚴格說它們的 raw 不是「模型自己的絕對尺度」,只有 `unidepth_v2` 與 `depth_pro` 是。

## 14. ✅ 第 3 項:接地點不可用時,哪一種方法還活著(2026-09-16)

### 14.1 為什麼要測這個

精度上深度模型打不贏幾何管線(2–4% vs 7.0%,而且還不是同條件)。
所以「深度模型的價值」不能建立在準度上,要建立在**幾何法做不到的事**上。

幾何法的地面平面公式 `d = A/(py − y_h)` **只對地面上的點成立**。
本專案已記錄過三個因此失效的情境:貼身目標車接地點低於 hood 線、
擦身而過時接地點沿車身遷移、急煞俯仰破壞平面假設。

### 14.2 實驗設計

⚠ 原本想找「底部被他車遮擋」的真實案例,**盤點後放棄**:高速公路跟車畫面裡
前車就是最近的物體,seg21 的 100 幀裡只有 1 幀符合;而「接地點低於 hood 線」
在這台相機上不存在(8.4 m 的車接地點還在 py≈503,離 hood 線 700 很遠)。

改成一個**直接而且可控**的測法:同一台車、同一組影格、同一個雷達真值,
只把取樣點從**接地點**換成**車身中心**(遮罩像素的中位位置)。
車身中心比接地點高 **17–23 px(中位)**,而且**永遠看得見**——
接地點被擋住時你還有它。

### 14.3 結果(近場 <32 m,scaled 中位相對誤差 %)

| 方法 | 接地點 seg10 | 接地點 seg21 | **車身中心 seg10** | **車身中心 seg21** | 退化 |
|---|---|---|---|---|---|
| **方法 C 古典幾何** | 3.11 | 5.59 | **102.03** | **141.10** | **✗ 約 30 倍** |
| `metric3d_v2` | 2.09 | 2.82 | 1.65 | 1.60 | 0.7× |
| `unidepth_v2` | 2.33 | 2.67 | 2.36 | 2.66 | 1.0× |
| `da3_metric` | 3.22 | 3.01 | 2.44 | 2.89 | 0.9× |
| `depth_anything_v2_vits` | 4.20 | 3.49 | 4.56 | 3.27 | 1.0× |
| `depth_pro` | 9.27 | 8.85 | 9.07 | 9.69 | 1.0× |

**配對逐幀差的統計檢定(區塊自助 95% CI,20 幀/塊,n=227)**:

| 模型 | 車身 − 接地點 | 95% CI | 結論 |
|---|---|---|---|
| `metric3d_v2` | −0.30 | [−0.52, +0.05] | 無可測差異 |
| `unidepth_v2` | +0.14 | [−0.15, +0.50] | 無可測差異 |
| `da3_metric` | +0.11 | [−0.76, +0.41] | 無可測差異 |
| `depth_pro` | +0.27 | [−0.17, +0.90] | 無可測差異 |
| `depth_anything_v2_vits` | +0.30 | [+0.07, +0.83] | 接地點略好(顯著但微小) |

### 14.4 結論

**五個模型中有四個,把取樣點從接地點移到車身中心,誤差沒有可測的變化。
同一個移動讓幾何法從 3.11% 變成 102%。**

→ 深度模型**不需要接地點**;幾何法**必須**要接地點。
這是深度模型在本計畫裡真正的、不可取代的角色 —— 不是「比較準」,
而是**在幾何法沒有答案的地方仍然有答案**。

這也把計畫書「雙軌校正」的定位講清楚了:**兩軌不是互相驗證,是互相補洞。**

### 14.5 ⚠ 界定:這測的不是視覺遮擋

本實驗證明的是「**幾何法把接地點當成量測輸入,深度模型不用**」。
它**沒有**證明深度模型能抵抗真實的視覺遮擋——真的被擋住時,模型看不到的像素
也會影響它的推論,那是另一個未測的問題。

其他限制:只有兩段、同一台車(Chunk_1 只有一台車)、seg21 近場僅 43 列;
與 7.0% 仍非同條件比較(見 §12.4)。

## 15. ✅ 方法 C:純古典幾何標定(2026-09-16)

### 15.1 定位

報告要比較三種方法,差別只在**地面幾何從哪裡來**:

| | 方法 | 地面幾何 | 尺度 | 學習成分 |
|---|---|---|---|---|
| A | 現有管線 | SHARP 點雲擬平面 | 法定標線 + 虛線碼表 | 平面來自模型 |
| B | 計畫書 | 單眼深度圖 | 法定標線 | 全部 |
| **C** | **本節** | **車道線消失點** | **虛線週期** | **零** |

### 15.2 兩個步驟,都只用標線

**① 地平線列 y_h ← 車道線消失點**(`tools/lane_line_fit.py`,既有工具)

| 段 | 左線 | 右線 | 消失點 row |
|---|---|---|---|
| seg10 | x = −1.6158y + 1211.4 (n=20) | x = +1.5445y + 0.4 (n=18) | **383.2** |
| seg21 | x = −1.4047y + 1129.1 (n=37) | x = +1.3492y + 86.2 (n=40) | **378.7** |

**② A = h·f ← 虛線週期**(`tools/vanishing_point_range_calib.py`,本次新增)

同一條車道線上相鄰兩個虛線起點在路面上相距 `cycle`,所以

```
cycle = A · [ 1/(py_遠 − y_h) − 1/(py_近 − y_h) ]
A     = cycle / [ ... ]
```

每一幀給一個 A 估計,取中位數(Caltrans 高速公路 cycle = 14.63 m):

| 段 | 配對數 | **A** | IQR 散布 |
|---|---|---|---|
| seg10 | 303(292 幀) | **1153** | 0.7% |
| seg21 | 336(288 幀) | **1139** | 5.9% |

**兩段的 A 吻合到 1.2%** —— 同一台車、同一個相機,A 本來就該是常數。這是方法 C 自洽的證據。

### 15.3 ⚠ 為什麼錨必須是「沿行進方向」的

車道寬**不能**解 A。第 py 列上寬 W_m 的車道佔 `W_px = W_m·(py − y_h)/h`,
**焦距被消掉** → 車道寬只能定掛高,`A = h·f` 的 f 仍然未知。
只有**沿行進方向**的長度(虛線週期、軸距、漆線長)才能約束 A。

這與 CLAUDE.md 記過的錯誤同型:計畫書把車牌(38×16 cm)列為距離錨,
但車牌寬度在代數上無法驗前向尺度,只能驗掛高與俯角。

⚠ **順便否證了一個看似漂亮的自洽**:用車道寬解掛高,兩段得 **1.157 m vs 1.328 m,差 13%**
——同一台車不可能。各段內部 CV 0.01% 是假的(那些 pairs 本來就是從擬合直線算出來的,
不是獨立量測)。**車道線抽取才是方法 C 的瓶頸**,與 CLAUDE.md 既有記載一致。
所以本節**不使用**車道寬,只用消失點 + 虛線週期。

### 15.4 端到端 vs 原廠雷達(近場 <32 m,n=231)

| Δ 假設 | 中位誤差 |
|---|---|
| 0(不扣安裝偏移) | 10.57% |
| **2.0 m** | **3.06%** |

比值中位 1.105 → 方法 C 系統性高估,而雷達裝在**保險桿**、相機裝在**擋風玻璃**。
逐段獨立求最佳 Δ:

| 段 | 最佳 Δ | 該 Δ 下中位誤差 |
|---|---|---|
| seg10 | **1.90 m** | 2.84% |
| seg21 | **1.75 m** | 2.96% |

**兩段獨立求出的 Δ 吻合到 0.15 m,而且等於轎車保險桿到擋風玻璃的實際距離。**
這是外部佐證,不是事後湊出來的參數。

**固定 Δ = 2.0 m(取物理值,不是最佳值)的最終數字**:

| 段 | n | 中位誤差 | p90 | bias |
|---|---|---|---|---|
| seg10 | 188 | 3.03% | 11.00% | −0.07 m |
| seg21 | 43 | 3.72% | 10.24% | −0.78 m |
| **合計** | **231** | **3.06%** | 10.73% | |

### 15.5 三方對照(近場 <32 m,同一組配對幀)

| 方法 | 學習成分 | 中位誤差 | 需要接地點? |
|---|---|---|---|
| **C 古典幾何** | **零** | **3.06%** | ✅ 必須 |
| B 深度模型(最佳 `metric3d_v2`) | 全部 | 2.09 / 2.82% | ❌ 不需要 |

**接地點不可用時,只有 B 還活著。**

### 15.6 ⚠ 限制

1. **Δ 是唯一一個對雷達擬合的參數。** 但最佳值(1.75/1.90)與物理值(~2 m)吻合,
   且本節報的是**固定 2.0 m** 的結果,不是最佳值。
2. **y_h 與 A 在同一批段落上求得**,不是留出測試。不過整個標定**完全沒用到雷達**,
   所以對雷達比較仍是外部驗證。
3. 只有兩段、同一台車;seg21 近場僅 43 列。
4. `cycle = 14.63 m` 取自 Caltrans 規格。CLAUDE.md 警告過**週期是「每條路的常數」**,
   跨路類就會錯;台灣國道實測是 10 m 而非規範的 12 m,務必反驗。

## 16. ✅ 盲測協定:尺度常數不准看真值(2026-09-16)

### 16.1 為什麼 §12 的 `scaled` 還不夠

§12 的 `scaled` 欄用的常數是 `k = median(雷達 / 預測)` —— **常數是從被評分的那批資料本身擬出來的**。
它回答「相對幾何對不對」是合格的,但它**不能回答「這條鏈能不能部署」**:實務上現場沒有雷達,
k 必須另外來。深度文獻普遍只報這一欄,所以這個問題在文獻裡是隱形的。

本節把常數換成**現場拿得到的來源**,全程不碰雷達,再用雷達評分。兩種來源:

| 來源 | 怎麼來 | 部署時拿得到嗎 |
|---|---|---|
| **路面錨點** | 沿車道線的路面像素,距離由方法 C 幾何 `d = A/(py − y_h)` 給 | ✅ 任何有標線的畫面 |
| **車輛接地點** | 目標車遮罩底緣那個像素,距離同樣由方法 C 給 | ✅ 只要接地點看得見 |

素材:seg10 / seg21 各 60 幀 × 10 個路面錨點 = 600 列,配 §12 的同一批目標。
評分一律 `真值 = 雷達 + Δ`,Δ = 2.0 m(§15.4 的物理安裝偏移,兩段獨立求出 1.90/1.75)。

### 16.2 結果:差距由「校正點的種類」決定,不由「盲不盲」決定

近場 <32 m,中位相對誤差 %(seg10 n=188、seg21 n=43):

| 模型 | k 來自**路面** | k 來自**接地點**(標線) | k 來自**雷達**(上限參考) | 車身中心 @ 接地點 k |
|---|---|---|---|---|
| `metric3d_v2` | 20.22 / 25.32 | **3.62 / 4.93** | 3.78 / 6.23 | 3.12 / 4.28 |
| `unidepth_v2` | 20.06 / 23.82 | **3.04 / 2.67** | 2.72 / 2.53 | 3.17 / 3.11 |
| `da3_metric` | 21.30 / 25.79 | **4.16 / 5.54** | 3.64 / 4.15 | 2.84 / 4.49 |
| `depth_anything_v2_vits` | 14.81 / 24.78 | **4.24 / 4.15** | 3.93 / 3.94 | 4.49 / 4.52 |
| `depth_pro` | 22.90 / 28.10 | 10.25 / 9.28 | 10.59 / 10.75 | 9.55 / 9.02 |
| *(對照)* 方法 C 純幾何 | — | *3.03 / 3.72* | — | *102 / 141(§14)* |

**① 盲測本身幾乎不用付代價。** 把常數從雷達換成標線,四個模型的變動在 **−0.3 ~ +1.4 個百分點**
之間,有幾格甚至變好(標線常數不會吸收雷達配對的雜訊)。**§12 的結論不因盲測而動搖。**

**② 但校正點的種類會付出 5 倍代價。** 同樣是標線給的距離、同樣不碰雷達,
把校正點從車輛接地點換成路面,誤差從 3–5% 變成 20–28%。

**③ 車身中心(幾何法失效處)一樣是 3–4.5%。** §14 證明了幾何法在那裡會爆掉(102 / 141%);
這裡補上最後一塊:那個情境下的深度模型**不需要雷達也能校正**。

### 16.3 機制:模型自己對「路面」與「車輛」就不一致(不用任何真值即可量到)

取**同一影像列**上的兩個像素(|Δpy| ≤ 6 px):一個在路面、一個在目標車接地點。
兩點都在路面上、橫向只差約 1.5 m,**真實距離必然相同**——所以讀值比偏離 1.0 就是模型自相矛盾,
這個量**完全不需要真值**:

| 模型 | seg10(n=27) | seg21(n=19) |
|---|---|---|
| `metric3d_v2` | 1.147 | 1.082 |
| `unidepth_v2` | 1.147 | 1.159 |
| `da3_metric` | 1.122 | 1.085 |
| `depth_anything_v2_vits` | 1.164 | 1.123 |
| `depth_pro` | 1.072 | 1.054 |

**五個模型全部把路面放得比同距離的車輛遠 5–16%。** 這是共通行為,不是某一個模型的瑕疵。

剩下的差距來自**尺度隨距離漂移**:隱含 k 在路面上由 0.880(4–8 m)漂到 0.949(20–26 m),
在車輛上由 1.21(12–16 m)漂到 1.09(20–34 m)。路面錨點集中在 5–12 m、目標車在 15–30 m,
兩個效應相加就是那 25%。

→ **「一個全域常數」其實不是全域的:它隨表面種類與距離變**。
標準 median-scaling 協定把常數擬在被評分的那批點上,正好把這件事藏起來。

### 16.5 可以寫進報告的一句話

### 16.6 限制

1. **精度下限被校正來源綁住**:k 來自方法 C,而方法 C 自己是 3.03 / 3.72%。
   模型不可能系統性優於自己的校正源;它買到的是**覆蓋範圍**,不是更高的精度。
2. 仍是兩段、同一台車、seg21 近場僅 43 列(§12.4 的限制原封不動)。
3. 路面錨點取在 5–25 m、目標車在 10–47 m,兩者距離分布不重合 —— §16.3 已把這一項
   與表面種類效應分開量過,但要完全排除得重做一組「與目標同距離帶」的路面錨點。
4. `--delta-m 2.0` 是物理安裝偏移,不是擬合值;但它對所有模型共模,不影響排名。

## 17. ✅ 度量模型的「公尺」是餵進去的焦距乘出來的(2026-09-16)

### 17.1 在解決什麼

§12.3① 主張「`metric3d_v2` 的 raw 成績好,是因為我們餵的焦距假設恰好對這台相機幾乎正確」。
那是**推論**,不是量測。`--fx` 旗標(本次新增)讓它變成量測:同一批影格、同一組目標像素,
只改餵進去的焦距。

`metric3d_v2` 與 `da3_metric` 都吃內參;預設餵的是 SHARP 的固定 FOV 假設
`fx = 0.7955 × 寬 = 926 px`。這台相機(comma EON,1164×874)openpilot 記載的焦距是 **910 px**。

### 17.2 結果(seg10,近場 <32 m,n=188)

| 模型 | 餵入 fx | raw 中位誤差 | 需要的 k | **k · fx/926** | scaled |
|---|---|---|---|---|---|
| `metric3d_v2` | 650 | **37.05%** | 1.588 | **1.115** | **3.78%** |
| | 910(記載值) | 11.86% | 1.135 | **1.115** | **3.78%** |
| | 926(預設) | 10.32% | 1.115 | **1.115** | **3.78%** |
| | 1200 | 16.22% | 0.860 | **1.115** | **3.78%** |
| `da3_metric` | 650 | 30.38% | 1.436 | **1.008** | **3.64%** |
| | 926(預設) | **3.69%** | 1.008 | **1.008** | **3.64%** |
| | 1200 | 28.53% | 0.778 | **1.008** | **3.64%** |

### 17.3 三個可以直接引用的結論

**① 模型的公尺與餵進去的焦距是嚴格 1:1。**
`k · fx/926` 這一欄在四個 fx 下**逐位相同**(1.115 / 1.008)——
也就是 `預測距離 ∝ fx`,沒有任何非線性、也沒有模型自己的判斷。
**光是換焦距就能讓 raw 誤差在 3.69% 與 37.05% 之間跑**,影像與模型一個位元都沒動。

**② 餵「正確的」焦距救不了 raw。**
讓 raw 歸零所需的 fx 是 `926 × k`:`metric3d_v2` 要 **1032**、`da3_metric` 要 **933**,
而這台相機真正的焦距是 **910**。所以 `metric3d_v2` 還有 **13%** 是模型自己的偏差,
與內參無關 —— 證據是餵記載值 910 反而更差(11.86% > 10.32%)。
**`da3_metric` 那個漂亮的 3.69% 是運氣**:它需要的 933 剛好落在我們餵的 926 旁邊 0.8% 內。

**③ 錨定之後焦距完全無關。** scaled 欄在所有 fx 下**一模一樣**(3.78 / 3.64)。
一個全域常數會把焦距誤差整個吸收掉 —— 這正是本專案用法定標線錨定尺度的理由,
也說明「先把內參估準再用度量模型」這條路線在本用途下是多餘的。
