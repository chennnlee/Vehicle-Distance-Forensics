# 已知失效邊界

誠實標示失效是本計畫的要求:以下情況系統會標示 no-lock / 遠場 / 拒發,或列為不可信,**不要當成 bug「修掉」**。

**🔴 cycle 是「每條路的常數」,不是「每支片的常數」(2026-08-17 由 comma2k19 診斷更正確立)**:
片段若跨越路類,單一 cycle 假設就在跨界處系統性倍速。comma2k19 那批 24 段是用「中位速 ≥ 70 km/h」
篩的,結果放進**起點在有紅綠燈市區幹道、後段才上 I-280** 的段;市區幹道虛線週期約是高速公路的一半
(實測 7.39m vs 14.63m)。半週期率是**位置的階梯函數**:沿共用走廊 lat 37.690 以南 0.0%、
37.710–37.715 為 39.0%、37.715–37.720 為 **90.4%**(那裡畫面直接看得到紅綠燈與短虛線)。
排除幹道段:端到端 MAE 10.54 → 5.32。**碼表量到的是真實週期,錯的是我們餵了錯的常數。**
→ 跨路類的片必須事前依路類切分,否則就得逐段反推週期。台灣案例沒踩到純屬運氣(素材都是整片同一路類)。

**🔴 路類不只兩種,而且速度完全代理不了(2026-08-18,comma2k19 車 2)**:除了「市區幹道 vs
高速公路」,還有**第三種**——高速連接道,實測週期約 **10 m**(既非 14.63 也非 7.32)。
車 2 的 `2018-06-12--00-59-15_7` 全程 **90–96 km/h 定速**穿過它:沿路量到 7.61 → 10.5 → 9.6 → 14.72,
單段 MAE 40.44,把車 2 的整體 MAE 從 2.49 拉到 4.23。**「最低速 ≥ 60」這條選段規則擋不住它**——
速度不只不能代理「幹道 vs 高速公路」,連「連接道 vs 主線」也代理不了。
可用的判別量是**段內週期離散度**`(p90−p10)/p50`:該段 0.70,其餘 32 段全部 ≤ 0.05(差 14 倍),
但**它用到真值,只能事後 characterise,不能當事前選段規則**。
→ 真正可部署的免真值版本是**物理連續性**:1.44 倍的速度階躍在幾幀內不可能。現行 `_join_octaves`
只對八度跳躍收費,1.44 倍不是八度所以漏掉;把轉移項推廣成「罰任何超過物理加速度上限的階躍」
應可自動旗標。**未實作、未迴歸**。

**🟡 夜間逆反射標記蓋掉漆線訊號(同上,2026-08-17;⚠ 大部分已修好,見下一段)**:排除幹道後,
剩下的成敗只由**照度**決定——高速公路段日間半週期率 **1.0%**(16 段中 16 段正好 0.0%)、
夜間 **11.9%**。逆反射路釘/貓眼把車燈的光直接反射回相機,夜間比漆線亮得多,亮度訊號的主週期
就變成它們的;日間漆線佔優、標記在量測上等於不存在。用**實測路面灰階**分組(不是時鐘,因為
隧道與無照明高速公路是同一問題):24 段落在 56.0–64.0 與 69.5–76.0 兩群、中間完全空白,
門檻取在那道空隙。夜間**確實有交錯幾何**(同一條 I-280:日間 271 窗全週期/25 半週期,
夜間 37/249),但五個形狀特徵(寬度/峰銳度/面積/振幅/縱向跨列高度)全部分不開 →
**單窗內無解**。台灣國道貓眼是 2× 方向、加州是 ½ 方向,**兩側都只在暗處發作**。
修好後夜間殘留 3.2% 半週期幀、MAE 4.72(日間 1.78),仍是已知的較弱情境。

✅ **修法:基頻選擇改成跨時間聯合決策(`_join_octaves`,2026-08-17)**——每個取樣點跑 Viterbi,
發射項用原本的諧波梳狀分數,轉移項對隱含速度變化收費;候選只取該幀自相關真有的峰(不無中生有),
所以真實加減速自由跟隨、只有「跳八度再跳回」變貴。**轉移項必須尺度不變**:第一版罰絕對 |Δv|
把台灣封存打壞(dc003 覆蓋 57.8→27.1、wow001 中位 89.4→77.9、hs006s 動 229 幀)——
低一個八度的路徑速度變化也低一個八度、永遠更平滑,等於獎勵減半;改罰 **|Δ log v|** 後兩者代價相同。
成效:夜間 MAE 12.46→**4.72**、p90 76.66→**3.58**、覆蓋 82.7%→**90.2%**(八度一致後分裂鎖閘
少丟幀);日間 1.84→1.78。**台灣 15 案迴歸**:`--no-join-octaves` 對改動前模組 9,762 共同幀
**0 幀變動**(重構本身惰性);開啟後 12/15 案零變動、總變動 0.74%,**hs005/hs006s(有人工逐幀真值)
零變動**,dc003 14/15 與 dc006 1/1 朝鄰域共識變好。舊行為用 `--no-join-octaves` 重現。
詳見 `data/output/comma2k19_eval/README.md`。

⚠ **首跑(2026-08-10)寫成「漆線之間鋪路釘造成半週期誤鎖、且是速度閘控」——兩個部分都已證錯**:
(a) 交錯的脈衝列應在寬度/振幅/面積/峰銳度上逐個交替,實測**四個特徵都不交替**,誤鎖窗的交替對比
不比正確窗高、相鄰對一致率 0.53–0.72(擲硬幣 0.50)→ 該幾何不存在,「脈衝寬度匹配濾波判別器」
的前提不成立,**已放棄不必再試**;(b) 速度相依是混淆變項(幹道段與夜間段剛好也是慢的)。
lag 下限 0.25s 仍是真的**可達性**上界(次級週期只在 `v ≤ cycle_sub/lag_min` 內可搜到),但不是成因。
已排除的其他解釋:搜尋帶寬(±120→±60 幾乎沒變)、自動挑點跨線(與 MAE 無相關)、
取樣率(10.4 幀/週期,高於下面那條判準)。

**🔴 碼表取樣率下限(2026-08-03 由 KITTI 實跑發現)**:碼表需要**每個虛線週期 ≳8 幀**,
即 `fps ≳ 8 × v / cycle`。KITTI 10 Hz、85 km/h、週期 11.7m → 只有 **5.0 幀/週期**,
½ 與 2× 的假峰都落在搜尋範圍內,諧波梳狀評分無法分辨 → 反推週期出現三峰(5.9/11.7/23.4m),
整體 MAE 24.7,但**只看鎖對八度的幀 MAE 只有 2.27** → 壞的是八度選擇不是量測鏈。
加大視窗反而更糟(正確群 52%→20%→15%,長窗給倍週期別名更多支持)。
本專案成功案例都在 8.4–15.4 幀/週期(c1416u 8.4、wow001 10.8、hs005 11.3、dc006 12.7、dc007 15.4)。
→ 公開資料集要報管線 B 數字必須用 ≥25 fps 來源;10 Hz 自駕資料集在高速段本質不夠用。

**🔴 擦身而過的側向目標,速度不可信(2026-09-01,dc008 id250 實證)**:路邊停放廂型車在
接近過程中量到的距離**先變大**(32.8→34.2 m)才驟降,橫向漂 2.2 m,量到的接近率只有自車速的
**−0.02 倍(應為 1.00)**。原因是**接地點沿車身遷移**(從車尾滑到車側/車頭),是系統性效應不是雜訊。
→ 橫向偏移大且距離近的目標,只報距離、不要報速度。(這也是台灣端「零速錨」不可用的原因。)
